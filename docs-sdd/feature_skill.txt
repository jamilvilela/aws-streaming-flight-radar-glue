o glue job:
deve ter um arquivo main.py que inicializa o spark 4.0 e lib aws glue 5.1, faz o parse dos parametros e instancia uma classe Processor;
deve ter uma classe Processor que será responsável por orquestrar a leitura, as transformações e a escrita dos dados;
deve ter uma classe Config responsável por ler o arquivo de configuração em formato json com as configurações das origens e suas caracteristicas, e devolver um objeto parsed com os dados do json.
deve ter uma classe Reader responsável pela leitura dos dados recebidos no s3 em streaming com a funcionalidade job bookmarks e checkpointing. Esta classe deve receber os parametros de configurações origens e suas caracteristicas, fazer a leitura dos arquivos e entregar um dataframe spark como saida.
deve ter uma classe DataQuality que receberá o dataframe da leitura e deverá aplicar regras de cleasing e validações dos tipos de dados esperados, e conversão do dataframe no schema definido. A classe deve retornar um dataframe valido para o fluxo do Processor. a classe deve ter uma forma de que registros inválidos  sejam enviados para uma pasta Rejected no bucket Landing. A classe DataQuality deve ser capaz de ler o schema da origem no arquivo de configuração .json e fazer as validações de forma dinamica para qualquer origem baseado nos tipos dos dados.
deve ter uma classe Writer responsável por receber o dataframe com dados validos e armazenar em uma tabela da camada raw, e esta tabela será informada atraves de parametros no arquivo de configuração .json contendo informações de database, table name, partitions name (list)
deve contemplar apenas a entidade "flights" vinda do DMS, e as outras entidades serão tratadas em outros processos de carga.

artefatos complementares:
-testes unitarios com pytest fazendo mock de spark e glue e demais serviços aws, com cobertura de 100% do codigo;
-modulo de testes de integração com lib boto3 acessando diretamente os serviços aws implementados e ou utilizados neste projeto, por exemplo glue, s3, tabelas do catalogo. os testes devem contemplar validação de implementações dos serviços, validação de existencia dos serviços utilizados, conferencia dos dados lidos e dos dados escritos pelo glue job.
-scripts bash para setup e rollback no ambiente aws via terraform, ajustando os scripts existentes em rollback-setup.sh e setup-env.sh.
-scripts python pyspark podem ser implemantados utilizando data class, annotations, design patterns se for interessante e se for padrão no mercado de engenharia de dados, mas caso nao seja interessante para este projeto, implementar conforme melhores praticas.
-utilizar spark config para otimizar processamento e uso de memoria do cluster.
-sugerir novo schema para tabela etl_control com informações relevantes do processamento.
